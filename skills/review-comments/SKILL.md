# コードコメントを点検する

差分で追加・変更したコメントと、変更で古くなった周りのコメントを点検して直す。コメントの読み手は、将来このコードを読む人であり、PR のレビュアーではない。

サブエージェントを使えるなら、次の 3 つの観点をそれぞれ別のエージェントに点検させる。

## 不要なもの

- **レビュアーへの説明**: 変更の経緯やレビュアーへの説明を書いていないか。commit メッセージか PR 本文に移す。
- **コードの繰り返し**: コードを読めば分かることを書いていないか。
- **git にある情報**: 変更履歴、作者、日付を書いていないか。
- **コメントアウトしたコード**: 残っていないか。

## 書くべきこと

- **コードから読み取れないこと**: なぜそうするのか、守るべき前提や制約が書いてあるか。
- **正しさ**: コードと食い違っていないか。
- **TODO**: 何をいつやるかが書いてあるか。

## 品質を上げるもの

- **名前や構造**: コメントではなく、名前や構造で表せないか。
- **簡潔さ**: もっとシンプルに書けないか。

消すか残すか判断がつかないものは、直さずに理由を添えてユーザーに報告する。
