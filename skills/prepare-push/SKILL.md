# push する前の準備

この skill は順番だけを決める。各手順の中身は、それぞれの skill やツールに任せる。PR の作成はこの skill に含めない。

まず、PR にレビュアーがアサインされているかを確かめる。分からなければ、アサイン済みとして進める。

## レビュアーのアサイン前

1. **rebase**: 最新のベースブランチに rebase する。
2. **簡潔化**: 変更を簡潔にする (`simplify` skill があれば使う)。
3. **コードレビュー**: コードレビューをする (`code-review` skill があれば使う)。
4. **コメントの点検**: `review-comments` skill でコメントを点検する。
5. **指摘の修正**: 2〜4 の指摘を直す。直した差分が大きいときや、重大な指摘があったときは、2〜4 をもう一度行う。
6. **動作確認**: テストと lint を通し、変更した機能を実際に動かして確かめる。
7. **commit の組み替え**: レビューしやすい単位に commit を組み替える。各 commit でテストは回さない。
8. **最後の rebase**: ベースブランチが進んでいたら、もう一度 rebase する。ここからのテストは CI に任せる。

## レビュアーのアサイン後

push 済みの履歴は書き換えない。

1. **commit を積む**: 修正ごとに commit を積む。
2. **点検と動作確認**: アサイン前の 2〜6 を、今回の修正の差分に対して行う。
3. **未 push の commit の整理**: まだ push していない commit に限り、入れ替え・分割・集約してよい。

## push

ユーザーの指示がない限り push しない。
